# Локализация интерфейсов

Языки: русский (`ru`), английский (`en`), упрощённый китайский (`zh`).
Любой системный вариант китайского использует упрощённый перевод; неподдерживаемые
языки используют английский. По умолчанию выбран режим «Как в системе».
Выбор сохраняется локально на устройстве/в профиле браузера, независимо от сервера.

- WEB и админка: переключатель языка в шапке, общий localStorage для одного origin.
- Android и iOS: язык в настройках и мастере первоначального подключения.
- macOS и Windows: переключатель WEB-интерфейса сохраняет язык оболочки через
  ограниченный IPC; окна запуска и ошибки используют тот же язык при следующем запуске.
- Chrome/Edge: выбор языка на странице параметров расширения.
- Windows-установщик: определяет язык Windows и позволяет выбрать другой язык
  перед установкой. Он передаёт выбранный язык помощнику установки.

Переписка, названия задач, поручения, имена сотрудников, пользовательские названия
источников и ответы модели не переводятся. Язык интерфейса не меняет язык анализа
на сервере. Даты и диктовка используют выбранную локаль. Системные запросы разрешений
и название приложения в оболочке ОС используют язык, выбранный операционной системой.
Для прямых iOS push-уведомлений язык регистрируется на сервере вместе с устройством;
изменение языка этих уведомлений требует доступного сервера. Старые регистрации
сохраняют русский язык (миграция `0024.sql`).

## Изменение строк

`catalog.json` — общий источник переводов. Ключ — русский текст интерфейса;
`{0}`, `{1}` и т. д. — позиционные подстановки. Значения подстановок не переводятся
и не интерпретируются повторно. В Windows-помощнике сохранены спецификаторы Go printf.
Добавляйте вызов `tr(...)` / `i18n.Tr(...)` только в месте формирования текста интерфейса.
Не применяйте перевод ко всему DOM или к данным архива.

```sh
python3 localization/generate.py
python3 localization/generate.py --check
```

Генератор обновляет каталоги WEB, Android, iOS, Electron, расширения и Windows.
Результаты генерации хранятся вместе с исходниками, поэтому для сборки не нужен
внешний сервис переводов. iOS находится в отдельном репозитории `ios`:
его изменения, включая каталог и Xcode-проект, нужно сохранять отдельно.
После добавления Swift-файлов или ресурсов выполните `python3 ios/project.py`.

Стандартный перевод Inno Setup `windows/languages/ChineseSimplified.isl` взят из
https://github.com/jrsoftware/issrc/blob/main/Files/Languages/ChineseSimplified.isl
(версия сообщений 6.5.0+, совместима с закреплённым Inno Setup 6.7.3).
Авторские сведения сохранены в файле. Наши строки установщика генерируются в
`custom-messages.iss` по соответствиям `windows-messages.json`.

## Проверки

- `cd web && npm test` — системный язык, fallback, переводы WEB, исходный текст
  пользовательских записей, подстановки и существующие сценарии приложения.
- `cd macos && npm test` — выбор языка оболочки, сохранение предпочтения, IPC/SSO.
- Android `testDebugUnitTest`, `assembleDebug`, `assembleDebugAndroidTest`;
  инструментальный `net.muratov.assistant.LanguageTest` проверяет реальный каталог
  из APK, контекст ресурсов и сохранение выбора.
- iOS `LanguageTests` и `LanguageUITests`: три языка, подстановки, вкладки и
  сохранность исходного текста архива. Остальные тесты — регрессия.
- `cd backend && go test ./...`, с `TEST_DATABASE_URL` — миграция и обновление
  языка устройства; `cd windows && go test ./...` — помощник установки.

Сборка и публикация выпуска выполняются отдельно. Версии должны соответствовать AGENTS.md.

`desktop-catalog.json` дополняет общий каталог только для WEB/админки и Electron.
Здесь находятся строки управления дополнительными настольными компонентами
(например, Ollama), которые не используются мобильными клиентами. Генератор
объединяет этот файл с общим каталогом и проверяет подстановки тем же способом.
