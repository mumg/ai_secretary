# Правила проекта

## Версии при изменении кода

По требованию пользователя при каждом законченном наборе изменений кода в рамках
его запроса повышайте версию выпуска для Docker и Windows. По умолчанию повышайте
PATCH; для нового несовместимого контракта выбирайте соответствующий SemVer.
Не повышайте версию отдельно для каждого файла или промежуточного исправления
одного и того же запроса.

- Единая версия Docker и Windows хранится в корневом файле `version`.
- Одновременно обновляйте `backend/pyproject.toml` и значение `AppVersion`
  по умолчанию в `windows/installer.iss`.
- Docker-образы собирайте с `APP_VERSION` из `version` и отдельным тегом этой
  версии. Для компонентов сохраняйте суффиксы `-document-parser`, `-cert-init`
  и другие принятые в проекте суффиксы. Не ограничивайтесь тегами `local`,
  `latest` или датой исправления. Стабильные теги могут оставаться псевдонимами.
- Windows-сборка должна получать ту же версию из `version`, как уже делает
  `windows/build.ps1`. Не публикуйте другой код под ранее выпущенной версией.
- При изменении Android-кода также повышайте `versionCode` и `versionName`
  в `android/app/build.gradle.kts`.
- Перед завершением проверяйте согласованность версий. В отчёте различайте
  обновление исходников, сборку, публикацию и фактическое обновление прода;
  не заявляйте о публикации или установке без проверки результата.
