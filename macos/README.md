# AI Секретарь для macOS

Один **universal DMG для Apple Silicon и Intel**, macOS 13 Ventura или новее.
Electron открывает встроенный web-интерфейс. PostgreSQL 17, Go API, обработчик
задач, парсер PDF/DOCX/XLSX и Caddy входят в приложение; Docker, Homebrew,
Python, Node.js и Go на компьютере пользователя не нужны.

LLM и модель настраиваются в существующей панели: можно подключить Ollama
или OpenAI-совместимый сервер. Веса моделей, личные расширения из `extensions/`,
база и секреты других установок в DMG не включаются.

## Установка и работа

1. Откройте `AI-Secretary-<version>-mac-universal.dmg`.
2. Перетащите **AI Secretary.app** в «Программы» и запустите оттуда.
3. Первый запуск создаёт отдельную базу, ключи, сертификаты и службы.
4. Нажмите **Настройки** внутри окна и настройте модель и источники.

Службы зарегистрированы в `~/Library/LaunchAgents/net.muratov.secretary.*.plist`:

| Служба | Назначение |
| --- | --- |
| `database` | PostgreSQL, только 127.0.0.1 |
| `parser` | Парсер документов, только 127.0.0.1 |
| `api` | API, web и подключение к шлюзу, только 127.0.0.1 |
| `worker` | Получение и обработка данных |
| `proxy` | Caddy с HTTPS/mTLS, если настроен публичный домен |

Они запускаются **после входа пользователя**, перезапускаются при сбое и
продолжают работать после закрытия окна или выхода из Electron. При выходе
из учётной записи службы останавливаются. Сон Mac также приостанавливает работу.
Разрешите фоновую работу приложения в настройках macOS, если система её отключила.
Права администратора для пользовательских служб не требуются.

В приложении нет отдельного меню; настройки доступны кнопкой внутри окна.
Обычное закрытие приложения не останавливает сервер. Для остановки сервера:

```sh
open -na 'AI Secretary' --args --stop-services
```

Перед удалением `.app` удалите фоновые службы:

```sh
open -na 'AI Secretary' --args --remove-services
```

Обе команды запрашивают подтверждение. Удаление служб сохраняет данные;
повторный запуск приложения восстановит службы. Журналы находятся в каталоге
данных, указанном ниже.

## Данные, обновления и удалённое подключение

Корпоративный вход МТС Линк открывается в отдельном окне приложения и не требует
браузерного расширения. Приложение получает код из перенаправления МТС Линк и
передаёт его локальному серверу для обмена на токены. Окно входа изолировано от
основного интерфейса; его cookies и сессия удаляются после завершения или отмены.
При открытии панели во внешнем браузере доступен прежний вход через расширение.

Данные находятся в `~/Library/Application Support/AI Secretary` (доступ только
владельцу): `postgres`, `data`, `secrets`, `certificates`, `logs`, `backups`.
`connection.json` хранит локальные порты. Предпочтительные порты — 18000, 18080,
15432; при первой установке занятые порты заменяются свободными и сохраняются.
Отдельная роль `improver` не имеет прав суперпользователя PostgreSQL.

Серверные исполняемые файлы копируются из подписанного
пакета в версионный каталог `runtime`. Поэтому замена `.app` не обрывает работающую
службу, а фоновой работе не нужен запущенный Electron или смонтированный DMG.
Закройте Electron, замените `.app` новой версией и запустите: перед миграцией
приложение останавливает службы и создаёт холодную копию базы, вложений и ключей.
Старый runtime и копия сохраняются. Откат на меньшую версию и изменение кода под
тем же номером запрещены. При ошибке миграции старые API/worker не запускаются
автоматически; восстановление программы, БД и ключей выполняют вместе из копии.
Обновление major-версии PostgreSQL требует отдельной миграции.

Подключение Android через шлюз доступно в настройках **Удалённое подключение**,
в том числе в локальном режиме. По умолчанию входящие соединения извне закрыты.
Для прямого HTTPS-подключения:

1. Остановите службы командой `open -na 'AI Secretary' --args --stop-services`.
2. Укажите свой DNS-домен в `publicHost` файла `connection.json`, например
   `secretary.example.org` (без протокола). Остальные поля сохраните.
3. Перенаправьте внешние TCP 80 и 443 роутера на `httpPort` и `httpsPort` Mac
   (по умолчанию 18081 и 18443); DNS должен указывать на этот роутер.
4. Запустите приложение. Caddy получит и будет продлевать публичный сертификат;
   внешний доступ требует клиентского mTLS-сертификата из QR-кода.
   В настройках прямого подключения укажите этот же HTTPS-домен, если ранее
   настройки сервера уже были сохранены с другим адресом.

Порты выше 1024 позволяют Caddy работать без root. Настройка DNS/роутера и
получение публичного сертификата требуют сети и не выполняются сборщиком.
Чтобы вернуться к локальному режиму, остановите службы, очистите `publicHost`
и снова запустите приложение.

## Локальная сборка

Нужны macOS, Xcode Command Line Tools, Go 1.26, Node.js 24 (22.12+), Python 3.11+:

```sh
npm ci --prefix macos
npm test --prefix macos
node macos/node_modules/electron/install.js
macos/node_modules/.bin/electron macos/sso-smoke.cjs
python3 macos/build.py
node macos/smoke-test.cjs 'dist/macos/mac-universal/AI Secretary.app/Contents/Resources/server'
```

Результат: `dist/macos/AI-Secretary-<version>-mac-universal.dmg` и `SHA256SUMS`.
Версия берётся из корневого `version` и должна совпадать с `macos/package.json`,
`backend/pyproject.toml` и `windows/installer.iss`. Сборщик скачивает закреплённые
версии зависимостей, сверяет контрольные суммы, собирает Go для двух архитектур
и объединяет через `lipo`. Каждый Mach-O проверяется на наличие arm64 и x86_64
и отсутствие зависимостей от Homebrew или `/Applications/Postgres.app`.
Web и расширение браузера включаются из явного списка каталогов, без рабочих
данных. Лицензии поставляются в `Contents/Resources/server/third_party`,
дереве PostgreSQL и стандартных файлах Electron.
Неиспользуемые PostgreSQL-расширения PL/Python, PL/Perl и PL/Tcl не включаются,
так как им требуются отдельные интерпретаторы.

Smoke-тест создаёт временную установку с отдельными портами и метками launchd,
проверяет API, web, парсер, перезапуск, повторную установку и сохранность данных,
затем удаляет только свои службы и тестовые данные.

## GitHub Actions

Workflow **macOS universal DMG** (`.github/workflows/macos.yml`) запускается
для изменений приложения в `main`, pull request и вручную. Он собирает тот же
DMG, проверяет архитектуры, подписи и образ, затем запускает smoke-тест служб
из готового `.app`. Результаты доступны в artifact **macos-universal-dmg**.

Сборки `main` и тегов `macos-v*` используют **Developer ID Application** и
нотариализацию Apple. В Settings → Secrets and variables → Actions → Repository
secrets должны быть заданы пять секретов:

| Секрет | Значение |
| --- | --- |
| `MACOS_CERTIFICATE_BASE64` | Base64 файла `.p12`, содержащего сертификат Developer ID Application и закрытый ключ |
| `MACOS_CERTIFICATE_PASSWORD` | Пароль экспорта `.p12` |
| `APPLE_ID` | Email Apple Account для нотариализации |
| `APPLE_TEAM_ID` | Team ID из 10 символов, совпадающий с командой сертификата |
| `APPLE_APP_SPECIFIC_PASSWORD` | Пароль приложения Apple Account для `notarytool` |

Экспортируйте сертификат из «Связка ключей → Вход → Мои сертификаты» в `.p12`.
Закрытый ключ должен отображаться под сертификатом. Скопировать Base64:

```bash
base64 -i "$HOME/Documents/developer-id.p12" | pbcopy
```

Файлы `.p12`, пароли и ключи не добавляют в Git. Локальный профиль
`secretary-notary` не переносится на GitHub: workflow создаёт собственную
временную связку ключей, импортирует сертификат и проверяет учётные данные Apple.
Связка удаляется при завершении job, в том числе при ошибке. Секреты не передаются
в сборки pull request.

Если импорт `.p12` прошёл, но подходящий сертификат не найден, шаг
**Import Developer ID and validate Apple credentials** выводит только публичные
имена/отпечатки сертификатов и статус проверки. Сообщение различает причины:

- **Wrong certificate type** — нужен именно `Developer ID Application`;
  `Mac Developer`, `Apple Development`, `Apple Distribution` и
  `Developer ID Installer` для этой сборки не подходят.
- **does not match APPLE_TEAM_ID** — команда сертификата отличается от секрета;
  проверьте Team ID в скобках имени сертификата.
- **No code-signing certificate/private-key pair** — повторно экспортируйте
  сертификат вместе с закрытым ключом из «Мои сертификаты».
- **macOS does not consider it valid** — проверьте срок действия, отзыв и цепочку
  доверия. Промежуточные сертификаты Developer ID доступны на
  [официальной странице Apple PKI](https://www.apple.com/certificateauthority/).
- **Multiple valid** — экспортируйте в `.p12` только выбранный сертификат
  Developer ID Application с его ключом.

Локальная проверка: `security find-identity -v -p codesigning`. Для анализа
невалидных сертификатов уберите `-v`. После повторного экспорта обновите
`MACOS_CERTIFICATE_BASE64` и `MACOS_CERTIFICATE_PASSWORD` в GitHub Secrets.

Для первой проверки откройте Actions → **macOS universal DMG** → Run workflow:
ветка **main**, **sign=true**, **publish=false**. После успешного завершения
скачайте artifact **macos-universal-dmg**. Это подписанный universal DMG и
`SHA256SUMS`. Отчёты Apple доступны в **macos-notarization-logs**.
Изменения workflow и скриптов должны предварительно попасть в `main`.

Подпись серверных Mach-O выполняется до расчёта `files.json`, затем подписывается
объединённое universal-приложение с Hardened Runtime. Уже универсальные серверные
компоненты копируются один раз после объединения Electron: сборщик не обходит
тысячи одинаковых файлов PostgreSQL в каждой архитектуре. Лог показывает этапы
объединения, копирования, подписи отдельных файлов и отправки в Apple; во время
подписи каждые 30 секунд выводится текущий файл и прошедшее время. Подписи всех Mach-O
проверяются на принадлежность Developer ID указанной команды. Приложение
нотариализуется и получает прикреплённый билет до упаковки; затем аналогично
обрабатывается DMG. Проверяются Gatekeeper, билеты, контрольные суммы служб и
содержимое смонтированного образа. `SHA256SUMS` вычисляется после прикрепления
билета к DMG. При ошибке сертификата или Apple сборка завершается ошибкой.

Для публикации проверенного DMG создайте тег `macos-v<version>` либо запустите
workflow из `main` с **sign=true, publish=true**. Публикация без подписи запрещена;
существующие GitHub Releases не перезаписываются. Новый подписанный выпуск
нельзя устанавливать поверх другого содержимого с тем же номером версии.

Pull request, ручная сборка с **sign=false, publish=false** и обычный локальный
`python3 macos/build.py` используют ad-hoc подпись без нотариализации. Gatekeeper
может потребовать разрешить запуск через «Конфиденциальность и безопасность →
Всё равно открыть». Для локальной подписанной сборки с установленным Developer ID:

```bash
export MACOS_SIGNING_IDENTITY='Developer ID Application: Ваше имя (TEAM_ID)'
export MACOS_SIGNING_TEAM_ID='TEAM_ID'
export MACOS_NOTARY_PROFILE='secretary-notary'
python3 macos/build.py
```

Профиль предварительно создаётся через `xcrun notarytool store-credentials`.
Сборка загружает приложение и DMG в сервис нотариализации Apple; ключ подписи
остаётся в связке ключей. App Store Connect API key `.p8` для этого способа не нужен.

Использованные механизмы: [launchd от Apple](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html),
[защита Electron](https://www.electronjs.org/docs/latest/tutorial/security),
[Postgres.app universal binaries](https://postgresapp.com/downloads.html).

## Дополнительная локальная Ollama

Ollama можно установить позже из **Настройки → Модель → Локальная Ollama**.
Установка выполняется в профиль пользователя после инспекции компьютера;
модель загружается отдельно и проверяется до переключения рабочего LLM.
[Сценарий, требования и пользовательский LaunchAgent](../OLLAMA.md).
