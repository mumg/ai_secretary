# AI Секретарь для macOS

Один **universal DMG для Apple Silicon и Intel**, macOS 13 Ventura или новее.
Electron открывает встроенный web-интерфейс. PostgreSQL 17, Go API, обработчик
задач, парсер PDF/DOCX/XLSX и Caddy входят в приложение; Docker, Homebrew,
Python, Node.js и Go на компьютере пользователя не нужны.

LLM и модель настраиваются в существующей панели: можно подключить Ollama
или OpenAI-совместимый сервер. Веса моделей, личные расширения из `extensions/`,
база и секреты других установок в DMG не включаются.

## Установка и работа

1. Откройте `AI-Secretary-<version>-mac-universal.dmg`.
2. Перетащите **AI Secretary.app** в «Программы» и запустите оттуда.
3. Первый запуск создаёт отдельную базу, ключи, сертификаты и службы.
4. В меню **AI Секретарь → Настройки…** настройте модель и источники.

Службы зарегистрированы в `~/Library/LaunchAgents/net.muratov.secretary.*.plist`:

| Служба | Назначение |
| --- | --- |
| `database` | PostgreSQL, только 127.0.0.1 |
| `parser` | Парсер документов, только 127.0.0.1 |
| `api` | API, web и подключение к шлюзу, только 127.0.0.1 |
| `worker` | Получение и обработка данных |
| `proxy` | Caddy с HTTPS/mTLS, если настроен публичный домен |

Они запускаются **после входа пользователя**, перезапускаются при сбое и
продолжают работать после закрытия окна или выхода из Electron. При выходе
из учётной записи службы останавливаются. Сон Mac также приостанавливает работу.
Разрешите фоновую работу приложения в настройках macOS, если система её отключила.
Права администратора для пользовательских служб не требуются.

В меню есть запуск служб, открытие журналов, остановка сервера и удаление служб.
Обычное закрытие приложения не останавливает сервер. Перед удалением `.app`
выберите **Удалить фоновые службы…**. Эта команда сохраняет данные;
повторный запуск приложения восстановит службы.

## Данные, обновления и удалённое подключение

Данные находятся в `~/Library/Application Support/AI Secretary` (доступ только
владельцу): `postgres`, `data`, `secrets`, `certificates`, `logs`, `backups`.
`connection.json` хранит локальные порты. Предпочтительные порты — 18000, 18080,
15432; при первой установке занятые порты заменяются свободными и сохраняются.
Отдельная роль `improver` не имеет прав суперпользователя PostgreSQL.

Серверные исполняемые файлы копируются из подписанного локальной ad-hoc подписью
пакета в версионный каталог `runtime`. Поэтому замена `.app` не обрывает работающую
службу, а фоновой работе не нужен запущенный Electron или смонтированный DMG.
Закройте Electron, замените `.app` новой версией и запустите: перед миграцией
приложение останавливает службы и создаёт холодную копию базы, вложений и ключей.
Старый runtime и копия сохраняются. Откат на меньшую версию и изменение кода под
тем же номером запрещены. При ошибке миграции старые API/worker не запускаются
автоматически; восстановление программы, БД и ключей выполняют вместе из копии.
Обновление major-версии PostgreSQL требует отдельной миграции.

Подключение Android через шлюз доступно в настройках **Удалённое подключение**,
в том числе в локальном режиме. По умолчанию входящие соединения извне закрыты.
Для прямого HTTPS-подключения:

1. Выберите **Остановить службы и выйти…**.
2. Укажите свой DNS-домен в `publicHost` файла `connection.json`, например
   `secretary.example.org` (без протокола). Остальные поля сохраните.
3. Перенаправьте внешние TCP 80 и 443 роутера на `httpPort` и `httpsPort` Mac
   (по умолчанию 18081 и 18443); DNS должен указывать на этот роутер.
4. Запустите приложение. Caddy получит и будет продлевать публичный сертификат;
   внешний доступ требует клиентского mTLS-сертификата из QR-кода.
   В настройках прямого подключения укажите этот же HTTPS-домен, если ранее
   настройки сервера уже были сохранены с другим адресом.

Порты выше 1024 позволяют Caddy работать без root. Настройка DNS/роутера и
получение публичного сертификата требуют сети и не выполняются сборщиком.
Чтобы вернуться к локальному режиму, остановите службы, очистите `publicHost`
и снова запустите приложение.

## Локальная сборка

Нужны macOS, Xcode Command Line Tools, Go 1.26, Node.js 24 (22.12+), Python 3.11+:

```sh
npm ci --prefix macos
npm test --prefix macos
python3 macos/build.py
node macos/smoke-test.cjs 'dist/macos/mac-universal/AI Secretary.app/Contents/Resources/server'
```

Результат: `dist/macos/AI-Secretary-<version>-mac-universal.dmg` и `SHA256SUMS`.
Версия берётся из корневого `version` и должна совпадать с `macos/package.json`,
`backend/pyproject.toml` и `windows/installer.iss`. Сборщик скачивает закреплённые
версии зависимостей, сверяет контрольные суммы, собирает Go для двух архитектур
и объединяет через `lipo`. Каждый Mach-O проверяется на наличие arm64 и x86_64
и отсутствие зависимостей от Homebrew или `/Applications/Postgres.app`.
Web и расширение браузера включаются из явного списка каталогов, без рабочих
данных. Лицензии поставляются в `Contents/Resources/server/third_party`,
дереве PostgreSQL и стандартных файлах Electron.
Неиспользуемые PostgreSQL-расширения PL/Python, PL/Perl и PL/Tcl не включаются,
так как им требуются отдельные интерпретаторы.

Smoke-тест создаёт временную установку с отдельными портами и метками launchd,
проверяет API, web, парсер, перезапуск, повторную установку и сохранность данных,
затем удаляет только свои службы и тестовые данные.

## GitHub Actions

Workflow **macOS universal DMG** (`.github/workflows/macos.yml`) запускается
для изменений приложения в `main`, pull request и вручную. Он собирает тот же
DMG, проверяет архитектуры, подписи и образ, затем запускает smoke-тест служб
из готового `.app`. Результаты доступны в artifact **macos-universal-dmg**.

Для публикации проверенного DMG создайте тег `macos-v<version>` либо запустите
workflow из `main` с `publish=true`. Обычная сборка релиз не публикует.
Существующие GitHub Releases не перезаписываются.

Приложение внутри DMG имеет только ad-hoc подпись, **без Apple Developer ID и notarization**.
Gatekeeper может потребовать разрешить запуск через «Конфиденциальность и
безопасность → Всё равно открыть». Для распространения с подтверждённым издателем
нужно добавить сертификат Developer ID и нотариализацию; Android/Windows ключи
для этого не подходят.

Использованные механизмы: [launchd от Apple](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html),
[защита Electron](https://www.electronjs.org/docs/latest/tutorial/security),
[Postgres.app universal binaries](https://postgresapp.com/downloads.html).
