# Объединение почтовой переписки

Переписка группируется в пределах одного почтового источника. Сохраняются
`subject_key` (хеш нормализованной темы) и `subject_tokens` (множество токенов).
При нормализации убираются повторяющиеся Re/Fw/Fwd/Ответ/Пересылка и аналогичные
префиксы, включая Re[2], различия регистра и лишние пробелы. Пустая тема не
служит основанием для объединения.

Точное совпадение нормализованных тем объединяется без вызова модели.
Для остальных тем вычисляется коэффициент Жаккара: пересечение множеств
токенов / объединение множеств. Кандидат требует не менее двух общих токенов
и коэффициента не ниже 0,8. В сравнении участвуют слова, основные идентификаторы
и нераспознанные буквенно-цифровые обозначения. Даты, время, периоды, версии,
количества, нераспознанные числа и ссылки на связанные объекты не снижают
сходство темы, но передаются модели для проверки смысла.

В `Subject-Token-Classification` сохраняются исходный и нормализованный токен,
тип, роль (`primary` / `related`), пространство идентификатора, тип объекта,
уверенность и основание классификации. Распознаются известные форматы
INC/REQ/CHG/RITM, BI_2638, CPB.039, UUID и числа после названия объекта
(например, «задача №149053», «договор 145700»). Ведущие нули сохраняются.
Нераспознанные числа и буквенно-цифровые слова получают тип `unknown`.
Число `149053` без контекста не объявляется идентификатором автоматически.

Разные уверенно распознанные основные идентификаторы одного пространства
и типа объекта запрещают объединение. Проверяется вся найденная нитка, чтобы
письмо без номера не стало промежуточным звеном между разными заявками.
Несколько основных номеров неоднозначны и требуют проверки моделью.
Различающиеся ссылки «дополнение к …», даты и версии не являются жёстким запретом.

Для не более трёх подходящих ниток настроенная LLM (Qwen) получает обе темы,
авторов, даты, классификацию токенов и ограниченные фрагменты писем. Объединение выполняется только
при единственном подтверждённом совпадении с уверенностью не ниже 0,9.
Ошибка модели, неоднозначность или слишком много кандидатов оставляют нитки
раздельными. Решение и оценки сохраняются в `Subject-Thread-Match` заголовках
события; дальнейшие письма с той же нормализованной темой используют это решение.

`Original-Thread-Id` сохраняет идентификатор Exchange/IMAP для связи с календарём.
Связывание ниток не объединяет автоматически разные поручения: повторное
поручение с тем же названием обновляет активную задачу, сохраняя её ID и статус.

После миграции 0022 существующий архив можно обработать теми же правилами:

```sh
python -m improver.services.subject_reconciliation --apply
```

Без `--apply` изменения базы откатываются, однако вызовы LLM выполняются.
На время обработки архива остановите worker. Операция повторяема: сохранённые
решения повторно не запрашиваются у модели.
