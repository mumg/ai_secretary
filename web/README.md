# WEB-клиент Секретаря

Исходники рабочего клиента: `backend/web/app.html` и
`backend/web/assets/app{,-core}.js`, `app.css`.
Go-сервер отдаёт его по `/` и `/app/`, Caddy защищает тем же mTLS, что API.
Используется существующий API `/api/v1`; сторонних запросов и CDN нет.
Пакет устанавливает локальную копию markdown-it и его MIT-лицензию.
Обновление Docker-образа backend включает клиент; отдельный Node-сервер на
рабочем сервере не нужен. Пересборка assets при запуске также не требуется.

## Проверки

```sh
cd web
npm ci
npm test
npm run check
```

DOM-тесты запускают рабочий клиент с синтетическим API: операции с задачами,
контекст только по кнопке, устаревшие ответы поиска/деталей, ошибки сети,
Markdown/XSS, история чата, часовой пояс и прямые ссылки.
Серверные тесты находятся в `backend/internal/server` и запускаются через
`go test ./...` из `backend`. Для интеграционных тестов задайте
`TEST_DATABASE_URL` на **изолированную** PostgreSQL. Рабочую базу использовать
нельзя: тесты создают и удаляют собственные схемы.

После изменения версии markdown-it выполните `npm run vendor`, включите
обновлённый JS, лицензию и lock-файл в изменение, затем повторите тесты.

## Снимки для README

```sh
node preview.cjs
```

Откройте `http://127.0.0.1:8766/app/`. Это отдельный локальный сервер:
он отдаёт рабочий HTML/CSS/JS и синтетические ответы из `tests/fixtures.cjs`.
Операции меняют только тестовые объекты в памяти. Он не подключается к рабочему
серверу и не входит в Docker-образ. Скриншоты 1440×1000 сохранены в `assets/web/`.
Остановите сервер после работы сочетанием Ctrl+C.

## Поведение

- Две постоянные панели; на ширине меньше 590 px рабочая область прокручивается
  горизонтально, детали не заменяют список.
- Hash-ссылки содержат вкладку, тип и ID записи, поиск, сортировку и состояние чата.
  HTTP-перезагрузка такой ссылки возвращает оболочку `/app/`.
- Загрузка списков и деталей отменяет устаревшие запросы и проверяет их порядковый
  номер. Мутации не повторяются автоматически при потере сети.
- Запросы чата хранятся на сервере. История загружается страницами по 100 запросов.
- Обновления приходят по WebSocket; скрытая вкладка отключается, при возврате
  получает полную синхронизацию. Формы и черновики не перезаписываются.
  Протокол, резервный опрос и миграция описаны в [REALTIME.md](../REALTIME.md).
- Письма отображаются как текст, HTML из Markdown отключён, изображения не загружаются.
  Ссылки допускают только HTTP(S)/mailto. Источники с ID открываются в правой панели.
- Даты и ввод срока используют часовой пояс из `/api/v1/ui/config`; он не содержит
  секретов. Время внутри пропуска при переходе на летнее время отклоняется.
- Просмотр не запрашивает принудительную синхронизацию источников. При явном обновлении
  контекста клиент вызывает `POST /meetings/{id}/context/refresh`.

Браузерные push при закрытой странице, PWA, светлая тема, голосовой ввод и
полноценный офлайн-режим оставлены последующими расширениями. Текущая страница
показывает состояние подготовки и готовый ответ; push Android остаётся на сервере.

Во вкладке «Статус» очередь показана карточками и полосой прогресса. Скорость —
число успешно завершённых событий за скользящие 15 минут, делённое на 15;
ошибки и исключённые фильтрами события не учитываются. Время завершения анализа
фиксируется после ответов модели. При потере соединения последние значения
остаются на экране с отметкой об устаревании.

Браузер подписывается на `/api/v1/realtime?status=1`. Сервер передаёт полные
кадры `{"type":"status","data":{...}}` при подключении, после изменений
и каждые 5 секунд. `data` имеет тот же формат, что `GET /api/v1/system/status`.
Таб состояний не опрашивает этот HTTP endpoint. После переподключения приходит
новый полный снимок. Старые подписчики без `status=1` сохраняют прежний протокол.
