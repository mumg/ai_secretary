# Обновления WEB и Android

## Поведение

- WEB получает изменения задач, встреч, контекста, итогов, переписок, чата и
  состояния компонентов через `wss://<сервер>/api/v1/realtime`.
- Android держит один сокет на приложение, пока есть видимая Activity.
  Переход между списком, деталями и чатом не создаёт отдельные подключения.
  При уходе последней Activity в фон транспорт немедленно закрывается,
  таймеры переподключения останавливаются. При возврате выполняется синхронизация.
- Firebase сохраняет существующие правила фоновых уведомлений, включая
  готовность контекста только после ручного запроса будущей встречи.
  Автоматическое обновление по WebSocket само по себе push не создаёт.
- FCM остаётся резервной доставкой бизнес-уведомлений независимо от состояния
  сокета: сервер не подавляет push по ненадёжному признаку «устройство онлайн».
  Если push догнал уже открытое приложение, Android направляет его в поток
  обновлений и не показывает второе системное уведомление. Это закрывает гонку
  между сворачиванием приложения, потерей связи и доставкой push.
- На WEB невидимая вкладка отключается. Возврат, восстановление сети и
  переподключение приводят к повторному чтению данных. Черновик чата,
  выбранная запись и прокрутка сохраняются; обновление откладывается, пока
  открыта форма или выполняется действие пользователя.

## Протокол

Сервер отправляет короткие JSON-сигналы без текстов переписки и секретов:

```json
{"type":"changed","topics":["tasks","chat"]}
```

Темы: `all`, `tasks`, `meetings`, `contexts`, `results`, `threads`, `events`,
`chat`, `status`. Сигнал означает необходимость перечитать соответствующий
REST endpoint. При подключении сервер всегда передаёт `all`. Журнал событий
и курсор воспроизведения не требуются: актуальное состояние хранится в БД.

Сервер передаёт `{"type":"ping"}` с интервалом не более 20 секунд;
клиент отвечает текстовым кадром `pong`. Без ответа за 65 секунд соединение
закрывается. Клиенты обнаруживают отсутствие входящих сообщений за 60 секунд
и переподключаются с увеличением задержки примерно от 1 до 30 секунд и jitter.

При недоступном сокете Android выполняет резервную синхронизацию каждые
30 секунд, WEB — опрос списков каждые 30 секунд и открытого чата/готовящегося
контекста каждые 5 секунд. Дополнительные существующие короткие опросы Android
выполняются только в активном приложении и при отключённом сокете.
Состояние компонентов обновляется по сигналу сервера каждые 20 секунд:
доступность Ollama, истечение TTL и занятость блокировок могут меняться без
записи в архив. Раз в 5 минут передаётся `all` для сверки состояния и учёта
изменений календарного времени.

## Backend и развёртывание

Миграция **0021** добавляет PostgreSQL-триггеры. Они вызывают `pg_notify`
после изменения данных API, worker или внешним импортом. PostgreSQL доставляет
сигнал только после COMMIT, не после ROLLBACK. Одинаковые темы объединяются
внутри транзакции; API объединяет серии сигналов перед отправкой клиентам.
На каждого клиента хранится ограниченное множество тем, а не растущая очередь.
Записи только рейтинга/служебных отметок не запускают циклическое перечитывание.

Каждый процесс API имеет отдельное соединение LISTEN. После его восстановления
все подписчики получают `all`. Redis или отдельный брокер не требуются.
До восстановления LISTEN новые WebSocket-подключения отклоняются, и клиенты
используют резервный опрос.

Сначала выполните `alembic upgrade head`, затем обновите API и worker.
Минимальная версия схемы backend — 21. Старый Android продолжает работать
через REST и Firebase. WebSocket использует существующие клиентские сертификаты
mTLS; Caddy проксирует `/api/*` вместе с Upgrade. Браузерный Origin проверяется
до принятия соединения, подключения с другого сайта запрещены.

## Проверки

- `backend/tests/test_realtime.py`: Origin, протокол, heartbeat, объединение
  событий, COMMIT/ROLLBACK, отсутствие цикла ранжирования, восстановление LISTEN.
  Для тестов БД нужен `REALTIME_TEST_DATABASE_URL` на отдельную мигрированную БД.
- `web/tests/ui.test.cjs`: обновление списка/деталей и чата, сохранение черновика
  и прокрутки, остановка скрытой вкладки и синхронизация после возврата.
- `android/.../RealtimeLifecycleTest.kt`: изменение через настоящий API,
  автоматическое появление задачи, отключение в фоне, получение пропущенного
  изменения после возврата, замена соединения после изменения настроек.
  Тест запускается только с аргументом
  `realtimeTestServer=http://127.0.0.1:18768`, ADB reverse и временным debug-
  разрешением HTTP для localhost. На рабочем сервере тестовые задачи не создаются.
