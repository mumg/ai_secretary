# Локальная Ollama после установки приложения

В настольном AI Секретаре для Windows/macOS откройте **Настройки → Модель →
Локальная Ollama**. Переустановка AI Секретаря не нужна. В обычном браузере и при
удалённом доступе кнопки локальной установки не показываются.

1. Выберите **Локальная Ollama**. Проверка компьютера запускается автоматически.
   При несовместимости отображается причина, а установка блокируется.
2. При необходимости измените модель и контекст (по умолчанию `qwen3:4b`, 8192 токена).
   После изменения проверка ресурсов повторяется автоматически.
3. Нажмите **Использовать локально**. Приложение установит и запустит Ollama,
   загрузит модель, выполнит пробную генерацию и подключит её. Существующая
   работающая Ollama используется без повторной установки.

Во время установки видны текущий этап, progressbar и общий процент выполнения.
Процент учитывает этапы и фактически загруженные байты; на установке и пробном
запуске индикатор ждёт завершения этапа. 100% означает, что модель проверена и
подключена в серверных настройках. Остальные настройки и API-ключи сохраняются.
Ошибки и отмена не переключают рабочий LLM. Если ресурсов мало, выберите меньшую
модель или контекст; при ошибке проверки доступна кнопка повторной проверки.

## Инспекция и ограничения

Перед каждой установкой и загрузкой модели настольный процесс повторно проверяет
реальные параметры компьютера. Перед запуском скачанного установщика ресурсы
проверяются ещё раз. Данные о совместимости из браузера не принимаются.
Если инспекция или проверка размера модели не удалась, продолжение блокируется.

Требования встроенного механизма установки:

- Windows 10 22H2 (build 19045) или новее; macOS 14 или новее.
- x64 или ARM64; для x64 требуется AVX2.
- Минимум 4 логических ядра и 8 ГиБ доступной системе физической RAM.
- Для модели — дополнительно проверяемая оценка памяти: 125% размера слоёв модели
  плюс 3 ГиБ резерва и 0,5 ГиБ на каждые 4096 токенов контекста; минимум 8 ГиБ.
- Свободное место проверяется на томах установки, временных файлов и моделей.
  Если пути находятся на одном томе, требования суммируются. Резерв на томе —
  2 ГиБ; установка Windows — 5 ГиБ плюс 5 ГиБ временных файлов, macOS — 1+1 ГиБ;
  модель — 110% размера слоёв. После скачивания архив не учитывается второй раз.

Минимум ядер, AVX2 и запас памяти — **политика AI Секретаря для локального анализа**,
а не универсальные минимальные требования Ollama. Отдельная видеокарта не
обязательна: возможен CPU-режим. VRAM не прибавляется к RAM, чтобы не учитывать
унифицированную память Apple дважды и не предполагать совместимость GPU/драйвера.
Оценка не гарантирует скорость и точный расход памяти любой архитектуры модели:
поэтому перед переключением обязателен реальный пробный запуск.

Размер модели читается из официального реестра `registry.ollama.ai`. Для установки
нужен интернет; поддерживаются имена моделей этого реестра, без произвольных URL.
Путь хранения моделей — `OLLAMA_MODELS`, если переменная задана для приложения,
иначе `~/.ollama/models`. Для уже работающей сторонней Ollama со своим путём
хранения задайте такой же `OLLAMA_MODELS` при запуске AI Секретаря: удалённый API
не сообщает путь, а проверка диска выполняется по указанному локальному пути.

## Установка без администратора

Windows: официальный `OllamaSetup.exe`, параметры `/SILENT /CURRENTUSER /NORESTART`
и `/DIR` для `%LOCALAPPDATA%\Programs\Ollama`. Никаких `runas`, UAC или изменений
системных служб со стороны AI Секретаря. Процесс работает под обычным пользователем.

macOS: подписанный официальный `Ollama.app` распаковывается в `~/Applications`.
Проверяются SHA-256, подпись и Gatekeeper. CLI запускается через пользовательский
LaunchAgent `~/Library/LaunchAgents/net.muratov.secretary.ollama.plist` с адресом
`127.0.0.1:11434`. Системные `/Applications`, `/usr/local/bin` и LaunchDaemons
не изменяются. Существующая Ollama в `/Applications` может использоваться без
изменения её файлов. Её GUI не запускается автоматически, поэтому нет предложения
переместить приложение или установить системную ссылку CLI.

Ollama работает в пользовательской сессии; обработка на ней недоступна после выхода
этого пользователя из ОС. На macOS журналы находятся в `~/Library/Logs/AI Secretary`.
Чтобы отключить созданный LaunchAgent:

```sh
launchctl bootout "gui/$(id -u)/net.muratov.secretary.ollama"
rm ~/Library/LaunchAgents/net.muratov.secretary.ollama.plist
```

Модели и Ollama при этом сохраняются. В Windows используется штатное удаление
Ollama из списка установленных приложений.

## Целостность и проверка реализации

Версия и точные SHA-256/размеры официальных пакетов закреплены в
[`macos/ollama-release.json`](macos/ollama-release.json). Установщик запускается
только после полной проверки; произвольные адреса, команды и пути через IPC
передавать нельзя. Получателем IPC может быть только основной фрейм админки
в текущем окне и на точном origin локального сервера.

Источники требований и пакетов:
[Windows](https://docs.ollama.com/windows),
[macOS](https://docs.ollama.com/macos),
[официальный выпуск](https://github.com/ollama/ollama/releases/tag/v0.34.2).
Обновляя закреплённый выпуск, перепроверьте требования и оба пакета.

Проверки: `npm --prefix macos test`, `npm --prefix web test`,
`python3 localization/generate.py --check`. Они покрывают блокировку несовместимой
системы и обхода проверки, повторную инспекцию, целостность загрузки, IPC, пробный
запуск модели и явное переключение LLM. Установка реальных пакетов и работа GPU
на каждой целевой ОС проверяются отдельно при выпуске.

## Параметры работающей Ollama

Настройки запрашивают версию и `/api/ps` у локальной Ollama каждые 10 секунд,
пока раздел открыт. Для загруженных моделей показываются имя, контекст,
квантизация, общий объём памяти и объём на GPU. Доли CPU/GPU описывают размещение
модели, а не текущую загрузку процессора. Пустой список означает, что сервер
работает, но модели ещё не загружены в память; недоступность сервера отображается
отдельно, без устаревших данных.

Пробная генерация явно передаёт `num_gpu=-1`, как и рабочие запросы backend:
Ollama автоматически выбирает доступное ускорение и объём переноса на GPU.
При отсутствии совместимого ускорителя остаётся CPU; при недостатке памяти
возможно смешанное размещение. Наличие GPU само по себе не гарантирует, что
конкретная модель целиком поместится в его памяти.
