# Android-клиент

Kotlin-приложение использует Jetpack Compose, Room, закрытое хранилище клиентских ключей для mTLS и Firebase Cloud Messaging для обезличенных сигналов синхронизации.

## Сборка

```bash
./gradlew :app:assembleDebug
```

Минимальная версия Android — 8.0 (API 26), target SDK — 36.

## Складные устройства

С версии `0.6.0` на внутреннем экране складного телефона список и детали
отображаются рядом в двух равных панелях. До выбора элемента справа показана
подсказка. Выбор другой задачи, встречи или переписки заменяет детали;
переход из переписки в письмо сохраняет возврат назад. Чат также открывается
в панели деталей.

Jetpack WindowManager Activity Embedding отслеживает раскрытие, складывание,
поворот и изменение размера окна. При закрытии телефона выбранные детали
занимают весь внешний экран; после раскрытия список появляется рядом снова.
Выбранная запись, вкладка списка и черновик чата сохраняются. На устройствах
без поддержки Activity Embedding остаётся обычная навигация отдельными экранами.
Две панели включаются при ширине окна от 720 dp и меньшей стороне от 600 dp;
в узком окне многооконного режима используется один экран. Разделяющий сгиб
учитывается: вертикальный даёт панели рядом, горизонтальный — друг над другом.

Проверка на эмуляторе Pixel Fold со состояниями 0/1/2 (закрыт/полуоткрыт/открыт):

```bash
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=net.muratov.assistant.FoldableNavigationTest \
  -Pandroid.testInstrumentationRunnerArguments.foldableTest=true
```

Этот тест проверяет переключение панелей, сохранение выбранной задачи,
замену деталей, вложенную навигацию и черновик чата. Он временно использует
недоступный loopback-адрес, не обращается к production и восстанавливает
настройку подключения. Проверка самого макета не требует работающего сервера.

## Firebase

Перед реальной регистрацией FCM добавьте приложение `net.muratov.assistant` в Firebase-проект и поместите `google-services.json` в `app/`. Gradle подключит Google Services plugin автоматически. Без Firebase-конфигурации APK собирается, но push-токен не создаётся.

Для разработки Android отдельная лицензия не требуется. Условия и возможная стоимость Firebase зависят от выбранного тарифа и объёма использования; публикация через Google Play является отдельной процедурой и для локальной установки APK не нужна.

## mTLS

Публичный серверный сертификат должен быть доверен Android. С версии 0.7.0 клиентский ключ передаётся через QR-код из админской страницы и хранится только в закрытом каталоге приложения. Подробности — в разделе «Подключение через QR-код».

Подключение без клиентского сертификата недоступно. Прямой QR-код содержит
сертификат и ключ для mTLS; шлюзовой QR-код содержит ключи внешнего и внутреннего
соединений. Прежний адрес без сертификата требует повторного подключения через QR.

## Голосовой ввод

Обычное нажатие на `+` открывает форму ручного создания задачи. Долгое нажатие на `+`
запускает системное распознавание речи. Распознанная заметка отправляется локальному серверу,
где Qwen формализует название, описание, приоритет и срок выполнения задачи.
Приложение использует язык `ru-RU`, запрашивает разрешение `RECORD_AUDIO` и передаёт
службе Android предпочтение офлайн-режима. На устройстве должна быть установлена служба
распознавания и, для работы без сети, загружен русский языковой пакет. Конкретная системная
служба может игнорировать предпочтение офлайн-режима — это определяется прошивкой телефона.

## Первый запуск и подключение

Настройки открываются шестерёнкой в отдельной `SettingsActivity`.
Здесь доступны язык, подключение, руководители и подчинённые, обновления.
Кнопка «Назад» возвращает в приложение; отмена мастера подключения — в настройки.
Состояние компонентов открывается индикатором системы в верхней панели и не
занимает отдельный таб. Рядом встречные стрелки показывают связь с сервером;
до подтверждения соединения используется нейтральный цвет. Детали поручения
имеют заголовок и стрелку назад; обновление выполняется протягиванием вниз.

Начиная с `0.5.0` адрес сервера **не встраивается в APK**, в том числе из
`secretary.local.properties` или `-PsecretaryServerUrl`. На чистой установке
открывается мастер:

1. Нажмите «Сканировать QR-код» и считайте код камерой из админской страницы.
   Адрес и клиентский ключ заполнятся автоматически. Ручной ввод адреса недоступен;
   QR-код без клиентского сертификата не принимается.
2. Нажмите «Проверить и начать». Приложение проверит API и сохранит подключение
   только после успешного ответа.

Существующий явно сохранённый адрес и выбранный сертификат сохраняются при
обновлении. Повторно открыть мастер можно в настройках приложения. До настройки
приложение не подключается к серверу и не регистрирует устройство для push.
Серверу нужен сертификат HTTPS, доверенный Android; проверка доверия не отключается.

## Проверка обновлений

Сборка `playRelease` проверяет новую версию через Google Play, сборка `release`
— через RuStore. Проверка выполняется при открытии приложения и по кнопке в
настройках. При наличии обновления приложение открывает страницу своего магазина;
загрузка и установка целиком выполняются магазином. Приложение не скачивает APK,
не запрашивает разрешение на установку других приложений и не запускает установщик.
Проверка через API магазина работает после установки приложения из этого магазина.

GitHub Actions по-прежнему выпускает подписанный APK как отдельный артефакт, но
больше не публикует манифест обновлений и не обновляет канал `android-latest`.
Установки прежних версий, использующие этот канал, нужно перевести на магазин
вручную; для обновления с сохранением данных требуется совпадение подписи.

Обновление release поверх APK, подписанного debug-ключом или другим release-ключом,
невозможно. Для уже установленных release-сборок **сохраняйте один и тот же ключ
подписи**. Смена ключа без отдельного механизма ротации потребует переустановки;
удаление приложения удаляет его локальные настройки и данные.

## Публикация через GitHub Actions

Workflow [Android](../.github/workflows/android.yml) запускает тесты и сборку debug
при изменениях Android в `main`. Публичная release-сборка запускается тегом
`android-v<versionName>-<versionCode>`, например `android-v0.5.0-12`, или вручную:
**Actions → Android → Run workflow → main → publish**.

В **Settings → Secrets and variables → Actions** добавьте:

| Secret | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Постоянный keystore в Base64, одной строкой |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `ANDROID_KEY_ALIAS` | Alias ключа подписи |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |
| `ANDROID_GOOGLE_SERVICES_JSON_BASE64` | Необязательно: `google-services.json` в Base64 для FCM |

Например, на macOS можно скопировать keystore в Base64 в буфер обмена:

```bash
base64 -i /absolute/path/to/release.jks | tr -d '\n' | pbcopy
```

Не добавляйте keystore, его пароли или клиентские сертификаты в Git. Без четырёх
секретов подписи публикация завершается ошибкой. Ключ восстанавливается только
во временный каталог runner и удаляется после сборки. Release не содержит
встроенных клиентских ключей, паролей сертификатов и адреса частного сервера.
Firebase без опционального секрета отключён; WebSocket работает независимо от FCM.

Для выпуска увеличьте `versionCode` и `versionName` в `app/build.gradle.kts`,
отправьте исходники, затем создайте и отправьте соответствующий тег:

```bash
git tag android-v0.5.0-12
git push origin android-v0.5.0-12
```

Workflow публикует APK и `SHA256SUMS` в версионном релизе, без манифеста
самообновления. Уже опубликованный APK не заменяется новым файлом;
для новой сборки требуется увеличить версию. Для публикации используется
автоматический `GITHUB_TOKEN` с `contents: write`, отдельный GitHub PAT не нужен.

## Подключение через QR-код (0.7.2)

В админской странице сервера откройте «Удалённое подключение», выберите способ
подключения и нажмите «Показать QR-код». В Android откройте настройки подключения и
нажмите «Сканировать QR-код». Адрес сервера подставится автоматически. Нажмите
«Проверить и начать»: текущие настройки заменяются только после успешного запроса.

Для каждого кода сервер выпускает отдельный EC P-256 клиентский сертификат на год
(либо до истечения клиентского CA, если он истекает раньше). QR содержит адрес,
сертификат и приватный ключ непосредственно: доступ к незащищённому
публичному endpoint для регистрации не требуется. Код — секрет доступа, его
нельзя пересылать или сохранять скриншотом. Скрытие кода через две минуты, при
переключении раздела или уходе со страницы **не отзывает** сертификат и не делает
код одноразовым. Копия кода может быть импортирована повторно.

Начиная с 0.7.2 приложение читает компактные коды `AI-SECRETARY:D2:` (прямое
подключение) и `AI-SECRETARY:G2:` (шлюз), а также прежние JSON-коды обоих типов.
Новый формат: поля с двухбайтовой длиной в big-endian, сжатие zlib/DEFLATE и Base45
для алфавитно-цифрового режима QR. Поля прямого подключения: HTTPS-адрес UTF-8,
клиентский сертификат DER, 32-байтовый приватный скаляр P-256. Поля шлюза:
HTTPS-адрес, внешний клиентский сертификат DER и скаляр, SHA-256 внутреннего
серверного сертификата, внутренний клиентский сертификат DER и скаляр. UID
извлекается из URI клиентского сертификата. Приватные ключи проверяются на
соответствие сертификатам; отпечаток сервера проверяется при TLS-соединении.
Распаковка ограничена 16 КиБ; неизвестные версии и повреждённые пакеты отклоняются.
Показ компактного QR шлюза использует имеющиеся ключи и не требует перерегистрации.

С версии 0.7.4 API и realtime используют один общий WSS-туннель к шлюзу.
Внутри него передаются независимые потоки yamux; каждый сохраняет сквозной
TLS 1.3 с проверкой сертификата сервера и клиентским сертификатом. Отмена
запроса закрывает только его поток. При обрыве общего соединения все его потоки
завершаются; следующий запрос или переподключение realtime создаёт один новый
туннель. Если потоков не осталось, туннель закрывается после короткого простоя.
Нужна серверная поддержка `AI-SECRETARY-MUX/1`; сначала обновите сервер.
Сервер продолжает принимать отдельные туннели старых Android-клиентов.

Сначала обновите Android: версии до 0.7.2 не понимают новые коды.

Ключ хранится в `Context.noBackupFilesDir/client-identities/` с правами 0600,
каталог — 0700. Он не попадает в Android KeyChain, системное хранилище CA,
резервную копию или FileProvider. Приложение проверяет срок, назначение и пару
ключ/сертификат, использует ключ только с указанным в QR HTTPS-адресом и не
следует перенаправлениям при таком подключении. После успешной смены подключения
старые локальные ключи удаляются; при удалении приложения Android удаляет его
закрытый каталог. Ранее выбранные системные сертификаты поддерживаются для
совместимости, но новый мастер не устанавливает сертификаты в систему.

С версии 0.7.5 сканер использует ZXing 3.5.4 и встроенный резервный декодер
ML Kit для плотных QR. Модель входит в APK и не требует скачивания перед
сканированием. Камера работает с непрерывной фокусировкой; разрешение выбирается
по короткой стороне кадра в пределах 3 Мп, предпросмотр сохраняет весь кадр.
Кадры и содержимое QR не сохраняются в файлы или журналы приложения.
`DenseQRReaderTest` проверяет прямой QR с перспективой, неравномерным освещением
и нечётными размерами кадра; отдельно проверяется резервный декодер.

Тест `AppClientIdentityTest` декодирует PNG, созданный Go-сервером, импортирует его
и проверяет изоляцию ключа. Файлы в `src/androidTest/assets/mobile-identity/` —
**только тестовые**, подписаны отдельным тестовым CA и не входят в основной APK.
Для обновления фикстур из корня репозитория:

```sh
MOBILE_IDENTITY_TEST_FIXTURE_DIR="$PWD/android/app/src/androidTest/assets/mobile-identity" \
  go -C backend test ./internal/server -run TestMobileIdentityQRAndMTLS -count=1
```

## RuStore

Тексты карточки, иконка, требования к скриншотам и инструкция сборки AAB
находятся в [`rustore/README.md`](rustore/README.md).
Локальные сборки для загрузки хранятся в `rustore/artifacts/` и не попадают в Git.

Обычные телефоны используют только портретную ориентацию на всех экранах, включая сканер QR. На складных устройствах и планшетах поворот разрешён. Fold определяется по возможностям WindowManager, датчику шарнира и наблюдаемому FoldingFeature; обнаружение сохраняется для внешнего экрана.
Проверка ориентации на эмуляторах: запустите `OrientationDeviceTest` с аргументом
`orientationDevice=phone` для обычного телефона или `orientationDevice=fold` для Fold.
Сведения о возможностях устройства использует [Jetpack WindowManager](https://developer.android.com/develop/adaptive-apps/guides/foldables/make-your-app-fold-aware).
