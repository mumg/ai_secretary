# Парсер документов на Go

Отдельный сервис извлекает текст из PDF, DOCX и XLSX. Docker и Windows-служба
запускают `document-parser`; Python, LibreOffice, Poppler и внешние команды
конвертации не нужны. Go-зависимости зафиксированы в `go.mod` и `go.sum`.

## Запуск

Нужен Go 1.26. Из каталога `document-parser`:

```sh
go build -trimpath -o /tmp/document-parser ./cmd/document-parser
/tmp/document-parser serve --listen 127.0.0.1:8080
curl -F 'file=@example.docx' http://127.0.0.1:8080/extract
/tmp/document-parser healthcheck
```

`GET /openapi.json` сохраняет описание контракта прежнего сервиса.
`GET /health` возвращает `{"status":"ok"}`. `POST /extract` принимает multipart
поле `file` и возвращает прежние поля `text`, `media_type`, `truncated`, `metadata`.
Метаданные: PDF — `pages`; DOCX — `paragraphs`, `tables`; XLSX — `sheets`,
`non_empty_cells`. Ошибки имеют поле `detail`: 415 для неизвестного расширения,
413 при превышении размера, 422 для повреждённых/зашифрованных документов или
неверного multipart. Тайм-аут обработки — 504, тайм-аут ожидания свободного
обработчика — 503. Расширение определяет формат; MIME-тип возвращается исходный.

| Переменная | Значение по умолчанию |
|---|---|
| `MAX_BYTES` | `26214400` (25 МиБ) |
| `MAX_CHARACTERS` | `100000` Unicode-символов, включая разделители |
| `PARSER_TIMEOUT` | `30s`, загрузка и обработка запроса |
| `PARSER_CONCURRENCY` | `2` одновременных обработчика |

Документ обрабатывается дочерним процессом того же Go-бинарника; отмена запроса
или тайм-аут завершает процесс. В дочернем процессе задан мягкий лимит памяти
Go 192 МиБ, в Compose — общий жёсткий лимит контейнера 512 МиБ. Для Office ZIP
суммарный распакованный размер ограничен 128 МиБ и 10000 файлами. Windows не
использует контейнерный лимит памяти. Макросы и формулы не выполняются,
внешние ссылки не загружаются. PDF с паролем, включая пустой пароль, отклоняются.

Сохранены заголовки `[Страница N]`, `[Таблица N]`, `[Лист: Имя]`, порядок абзацев
перед таблицами DOCX, исходные формулы XLSX, числовые значения без форматирования
валют/процентов, даты и объединённые ячейки. PDF извлекается из текстового слоя;
OCR сканов отсутствует. Порядок текста в сложных многоколоночных PDF зависит от
порядка текстовых операторов и может отличаться от прежнего движка.

## Сборка и проверки

```sh
go vet ./...
go test -race ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o /tmp/document-parser.exe ./cmd/document-parser
# Из корня репозитория — все образы с версией из version:
./build-images.sh
```

Dockerfile использует корень репозитория как контекст и проверяет `APP_VERSION`
по файлу `version`. Тег парсера: `improver-backend:<version>-document-parser`.
В Windows `windows/build.py` собирает `parser/document-parser.exe` с той же
версией; WinSW запускает его на `127.0.0.1:18080`. Команда `version` показывает
встроенную версию выпуска, локальная сборка без `-ldflags` показывает `dev`.

Тесты Go работают без Python. Файлы в `testdata` и `expected.json` проверяют
результаты против прежней реализации, включая Unicode, усечение, таблицы,
Excel 1900/1904, формулы и PDF-шрифты/формы. HTTP-тесты запускают настоящий
дочерний бинарник, проверяют ошибки загрузки, шифрование, тайм-аут и `/health`
при занятом обработчике. CI выполняет тесты на Linux и Windows.

Python-реализация удалена. `tools/generate_fixtures.py` создаёт только входные
документы; зависимости находятся в `tools/requirements-fixtures.txt`.
Ожидаемые результаты `testdata/expected.json` сохранены и проверяются отдельно,
генератор их не перезаписывает. Python-тесты `tests/test_extractors.py` теперь
собирают и запускают настоящий Go-парсер через CLI:

```sh
python -m pip install -r tools/requirements-fixtures.txt
python -m unittest discover -s tests -v
```

Новую функциональность добавляйте в `cmd`/`internal`.
После изменения Go-зависимостей обновите поставляемые лицензии командой
`python3 tools/export_licenses.py` (только инструмент разработки).
