# Установщик AI Секретаря для Windows

Нативная установка для Windows 10 x64 начиная с **1607 / сборки 14393**,
Windows 11 x64 и Windows Server 2016/2019/2022/2025. Docker,
WSL и Python не нужны. Установщик включает Go-бинарники сервера, парсера и
установочного помощника, PostgreSQL 17, WinSW, Caddy и Visual C++ Runtime.
LLM и модель подключаются отдельно; в панели можно выбрать провайдера
с OpenAI-совместимым API. Частные интеграции из `extensions/` не включены.

База, API, парсер и обработчик писем работают на самом Windows-компьютере.
Совместимость конкретного сервера LLM с ранней Windows 10 проверяется отдельно;
можно подключить LLM по сети. Для интерфейса нужен современный Firefox, Chrome
или Edge (Chromium), совместимый с вашей версией ОС. Встроенные IE11 и Edge Legacy
не поддерживаются. Windows 7, Windows 10 1507/1511 и 32-разрядная Windows
в эту сборку не входят.

## Совместимость с ранними Windows 10

В версии 0.1.9 минимальная сборка установщика снижена с 20348 до 14393.
WinSW 2.12.0 поставляется в самостоятельном x64-варианте со встроенным .NET 6,
которому требуется Windows 10 1607+. Отдельно устанавливать .NET не нужно.
Go-бинарники, PostgreSQL 17 и Caddy остаются общими для всех поддерживаемых
выпусков. Visual C++ Runtime входит в EXE.

Перед настройкой базы проверяется запуск Go-сервера и парсера, PostgreSQL,
его утилит, WinSW и Caddy. Ошибка загрузки DLL останавливает настройку до создания
базы или перерегистрации служб. При обновлении предыдущие службы к этому моменту
уже остановлены и сохранены в резервной копии обычным процессом обновления.

Основания выбора компонентов: [Go](https://go.dev/doc/install),
[PostgreSQL на Windows](https://wiki.postgresql.org/wiki/Windows),
[целевые runtime WinSW 2.12.0](https://github.com/winsw/winsw/blob/v2.12.0/src/WinSW/WinSW.csproj),
[поддерживаемые Windows для .NET](https://learn.microsoft.com/en-us/dotnet/core/install/windows),
[минимальные версии Windows для Go](https://go.dev/wiki/Windows).

**Статус проверки:** CI выполняет установку на Windows Server 2022. Это не
подтверждает работу на Windows 10 1607; прогон на реальной сборке 14393 пока
не выполнен. Для него подготовлен отдельный режим smoke-теста ниже.

## Установка

Скачайте `AI-Secretary-Setup-<version>-windows-x64.exe` из
[GitHub Releases](https://github.com/mumg/ai_secretary/releases) и запустите
с правами администратора. Сборка EXE и smoke-тест установки выполняются workflow
**Windows installer**. Сборки из обычных push доступны как Actions artifacts;
публичные релизы создаются отдельным тегом или ручным запуском с `publish`.

Мастер предлагает выбрать:

1. Каталог программы (по умолчанию `C:\Program Files\AI Secretary`).
2. Порты интерфейса, парсера и базы: `18000`, `18080`, `15432`.
3. Доступ только с этого компьютера или публичный HTTPS-домен.

После установки откроется `http://127.0.0.1:18000/admin`: настройте AI-провайдера
(адрес Ollama или OpenAI-совместимого API), модель, источники и расписание.
Установщик не запрашивает адрес Ollama. В меню «Пуск» доступны приложение и настройки.
На общем рабочем столе создаётся ярлык «AI Секретарь» с иконкой приложения,
доступный всем пользователям ПК. Он открывает основное веб-приложение в браузере.
Источники и секреты вашей существующей Linux-установки в EXE не включаются.
Это отдельная установка со своей базой; перенос архива с Linux требует
отдельного резервного копирования и восстановления.

## Фоновая работа

Службы работают под встроенной учётной записью `LocalService`, запускаются
автоматически без входа пользователя и перезапускаются при сбое:

| Служба | Назначение |
| --- | --- |
| `AISecretaryDatabase` | Отдельный экземпляр PostgreSQL, только loopback |
| `AISecretaryParser` | Разбор PDF/DOCX/XLSX, только loopback |
| `AISecretaryApi` | API и web-интерфейс, только loopback |
| `AISecretaryWorker` | Синхронизация источников и обработка |
| `AISecretaryProxy` | HTTPS и mTLS, устанавливается для публичного режима |

Установщик создаёт отдельную роль базы `improver` без прав суперпользователя.
Параметры существующих PostgreSQL-инсталляций не меняются. Для первой версии
установщика используется встроенная локальная база; подключение внешней БД
через мастер пока не предусмотрено.

Данные находятся в `C:\ProgramData\AI Secretary`:

- `connection.json` — адреса и порты установки;
- `postgres` — база данных;
- `data` — вложения и рабочие файлы;
- `secrets` — ключ шифрования и пароли базы;
- `certificates` — клиентская CA и сертификат доступа;
- `caddy` — состояние ACME и серверные сертификаты;
- `logs` — журналы служб и `installer.log`;
- `backups` — резервные копии перед обновлением.

Доступ к каталогу данных ограничен администраторами, SYSTEM и LocalService.
Обычным локальным пользователям доступен web-интерфейс этого компьютера; это
режим локальной установки, а не разделение пользователей Windows на аккаунты.

## Мобильное приложение, HTTPS и DynDNS

Для внешнего доступа выберите HTTPS и укажите публичный DNS-домен без протокола.
**Нужен публичный IP либо DynDNS, указывающий на доступный извне адрес. На роутере
перенаправьте TCP 80 и 443 на Windows-компьютер. CGNAT без дополнительного решения
не позволяет принять входящие соединения.**

Установщик добавляет правила Windows Firewall только для Caddy на 80/443.
API, парсер и PostgreSQL продолжают слушать loopback. Caddy использует HTTP-01;
TLS-ALPN challenge отключён. Продление серверного сертификата автоматическое,
поэтому порт 80 должен оставаться доступным. DNS и роутер установщик не меняет.
Выдача сертификата произойдёт после запуска, когда домен и порты станут доступны.

Внешний доступ требует клиентского сертификата mTLS. Для экспорта запустите
PowerShell от имени администратора:

```powershell
& 'C:\Program Files\AI Secretary\setup\secretary-setup.exe' export-client `
  --root 'C:\Program Files\AI Secretary' --data 'C:\ProgramData\AI Secretary' `
  --output 'C:\Users\YOUR_USER\Documents\AI Secretary client'
```

В выбранном каталоге появятся `client.p12` и `client-password.txt`. Импортируйте
сертификат в браузер или Android KeyChain и выберите его в мастере мобильного
приложения. Пароль нужен при импорте. Клиентский сертификат выдаётся на два года;
автоматическое продление относится к серверному HTTPS-сертификату, не к нему.
Приватный ключ CA и `master-key` не передавайте на телефон.

## Обновление и удаление

Запустите новый EXE поверх существующей установки в том же каталоге.
Установщик сохранит текущие параметры подключения; страницы первоначальной
настройки при обновлении пропускаются. Установка более старой версии запрещена.

Новый `secretary-setup.exe` извлекается во временный каталог и выполняет
подготовку обновления до замены файлов. Это работает и для прежних установок
с Python-помощником. После успешного резервного копирования старый Python runtime удаляется
из каталога программы.

До замены файлов останавливаются компоненты, которые могут менять данные,
создаётся `pg_dump` базы, копия ключей, настроек и вложений, а также `program.zip`
с предыдущими исполняемыми файлами. Затем останавливается PostgreSQL,
обновляются файлы, выполняются миграции и проверяется готовность API.

Если резервное копирование не удалось, прежние службы запускаются обратно,
а замена файлов не начинается. При ошибке миграции API/worker остаются
остановленными: **автоматический откат базы не выполняется**. Проверьте
`logs\installer.log`, исправьте причину и повторите установку. Для возврата
к старой версии нужно согласованно восстановить программу, базу, вложения и
ключи из одной резервной копии. Не подменяйте только бинарные файлы после миграций.
Обновление major-версии PostgreSQL требует отдельной миграции.

Удаление через Windows останавливает и удаляет службы и программу, но
**сохраняет весь каталог ProgramData**, включая базу и резервные копии.
Повторная установка подключает сохранённую базу. Если программы и службы уже
удалены, перед миграцией создаётся холодная копия каталога PostgreSQL, ключей
и данных; она помечается `cold-cluster` в `upgrade-state.json`. Автоматическое скачивание и
установка Windows EXE пока не реализованы; новые версии доступны через ссылку
в меню «Пуск» и существующую проверку версии в web-панели.

## Сборка и публикация

На машине сборки нужны Go 1.26, Python 3.13 (только упаковка и тесты) и
Inno Setup 6.7.3. Python и его библиотеки не попадают в установщик:

```powershell
.\windows\build.ps1
```

Сборщик скачивает фиксированные версии сторонних компонентов и проверяет
SHA-256 из `vendor.json`, собирает ZIP расширения и включает только явно выбранные
исходники. Пользовательские `.env`, ключи, архив и конфигурация не упаковываются.
В EXE включены все зависимости для установки без скачивания из интернета;
для работы источников, модели и выдачи публичного сертификата сеть понадобится.

Workflow `.github/workflows/windows.yml` собирает EXE на `windows-2022` и проверяет
установку, готовность API/парсера, повторную установку с сохранением базы и ключа,
а затем удаление с сохранением данных. Публикация запускается только после
этих проверок тегом `windows-v<version>` (например `windows-v0.1.1`) либо через
**Actions → Windows installer → Run workflow → main → publish**.

Версия берётся из корневого файла `version`. Для нового публичного выпуска
увеличьте её, отправьте изменения и тег. Отдельный PAT для GitHub не нужен:
используется `GITHUB_TOKEN` с `contents: write`. Сборка не использует Docker Hub
или Android signing secrets. `SHA256SUMS` публикуется рядом с EXE.

EXE пока не подписывается сертификатом Windows Authenticode. Перед публичным
распространением от имени издателя можно добавить отдельную подпись Windows;
ключ Android для этого не подходит. Windows может показывать предупреждение
о неизвестном издателе.

`smoke-test.ps1` предназначен только для пустого одноразового Windows runner,
не запускайте его на рабочей установке. Установщик и данные теста не копируются
на ваш production-сервер.

Для проверки минимальной версии Windows 10 скопируйте EXE и `smoke-test.ps1` в чистую
одноразовую VM Windows 10 1607 x64. В **Windows PowerShell 5.0+ от администратора**:

```powershell
.\smoke-test.ps1 -InstallerPath '.\AI-Secretary-Setup-0.1.9-windows-x64.exe' -ExpectedWindowsBuild 14393
```

Сценарий проверит номер сборки ОС, установку служб, API и парсер, запуск встроенных
компонентов, повторную установку с сохранением базы и ключа, удаление с сохранением
данных. Тест обращается к локальному API; модель, почтовые источники и получение
публичного TLS-сертификата проверяются отдельно с тестовыми учётными данными.
Для интерактивной проверки откройте `/admin` и `/app/` в установленном браузере
до удаления приложения либо выполните обычную установку повторно.

API и worker работают через `backend/improver.exe`, миграции — через
`improver.exe migrate`. Парсер PDF/DOCX/XLSX запускается через
`parser/document-parser.exe serve`. Настройка, обновление, удаление, проверка
компонентов и экспорт сертификатов выполняются `setup/secretary-setup.exe`.
Версии всех трёх Go-бинарников
берутся из корневого `version`. Лицензии и перечни Go-зависимостей поставляются
в `third_party`, включая `third_party/document-parser` и `third_party/windows-setup`.

Проверки помощника: `go -C windows test -race ./...`. Они проверяют порядок
настройки и остановки служб, резервные копии, запрет отката версии, сохранение
ключей, PKCS#12 (в том числе от прежнего Python-помощника) и ошибки миграции.
Windows CI дополнительно запускает установку и удаление на настоящей ОС.
После изменения зависимостей обновите лицензии:
`python3 backend/tools/export_licenses.py --module-dir windows`.
