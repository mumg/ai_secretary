# Предконфигурация приложения

Файл `secretary-config.json` в UTF-8 задаёт начальные значения настроек LLM,
источников и остальных разделов админки. Готовый шаблон:
[`config/secretary-config.example.json`](config/secretary-config.example.json).
Это базовые значения, которые пользователь может изменять через обычные настройки.

Приоритет: встроенные значения → JSON установки → пользовательские значения в БД.
Файл не импортируется целиком в БД. При сохранении настроек записываются только
отличия от текущей базы значений. Например, если в JSON заданы сервер IMAP и порт,
а пользователь добавил имя и пароль, сервер и порт остаются в файле; в БД попадут
имя пользователя, зашифрованный пароль и изменение признака включения источника.
Пароли и API-ключи из JSON не возвращаются через API настроек.

Изменения файла вступают в силу после перезапуска **API и worker**. На macOS нужно
полностью завершить приложение и его серверные службы, затем запустить приложение;
одного закрытия окна недостаточно. В Windows перезапустите службы
`AISecretaryApi` и `AISecretaryWorker`. В Docker пересоздайте оба контейнера.
Заменяйте файл атомарно и обновляйте оба процесса одновременно.
Пользовательские отличия сохраняют приоритет после замены JSON. Если пользователь
сохраняет значение, равное значению из файла, соответствующее отличие удаляется
из БД, и поле снова наследует JSON. Пустая строка, `false` и пустой список считаются
явными значениями; списки заменяются целиком.

Существовавшие до подключения файла настройки БД сохраняют приоритет. Источник,
созданный пользователем до появления одноимённого `sources[].id` в JSON, остаётся
пользовательским и не переводится автоматически на наследование.

## Windows: политики и тихая установка

Политика может положить файл в корень установки:
`C:\Program Files\AI Secretary\secretary-config.json`.
API и worker читают его от имени `LocalService`; файл должен быть доступен этому
пользователю для чтения. Файл не удаляется при обновлении или переустановке.

Либо передайте файл установщику, например из пакета корпоративного развёртывания:

```powershell
.\AI-Secretary-Setup-0.7.20-windows-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CONFIGFILE="C:\Deployment\secretary-config.json"
```

Установщик копирует его в корень установки до запуска миграции и служб.
При следующих обновлениях без `/CONFIGFILE` используется ранее размещённый файл.

## macOS

Положите файл рядом с `.app`, например:

```text
/Applications/AI Secretary.app
/Applications/secretary-config.json
```

Файл находится снаружи подписанного приложения, поэтому его можно доставить
политикой MDM отдельно от DMG. При переносе `.app` разместите файл рядом с новым
расположением и перезапустите приложение, чтобы обновить пути служб launchd.
В режиме разработки используется `secretary-config.json` в корне репозитория.

## Docker

Используйте дополнительный Compose-файл, который подключает один и тот же JSON
к миграции, API и worker:

```sh
export APP_VERSION="$(cat version)"
export APP_CONFIG_PATH=/absolute/path/secretary-config.json
docker compose -f compose.yaml -f compose.preconfigured.yaml up -d --build
```

Для встроенной Ollama замените `settings.llm.base_url` в примере на
`http://ollama:11434` и подключите обычный для вашей установки Compose-профиль LLM.
Адрес `127.0.0.1` внутри контейнера относится к самому контейнеру.

## Самостоятельный запуск сервера

`APP_CONFIG_FILE=/absolute/path/secretary-config.json` указывает обязательный файл.
Если он отсутствует или некорректен, запуск завершается ошибкой без вывода содержимого.
Без переменной сервер ищет необязательный `secretary-config.json` рядом с бинарным
файлом. Установщики задают стабильный необязательный путь через
`APP_CONFIG_DEFAULT_FILE`; явный `APP_CONFIG_FILE` имеет приоритет.
Без файла сохраняется обычная настройка приложения через админку.

## Формат

- `schema_version`: обязательное значение `1`.
- `settings`: необязательные разделы и поля обычных настроек админки, например
  `llm`, `calendar`, `identity`, `relationships`, `analysis_filters`, `worker`.
  Неизвестные поля и неверные типы отклоняются. Параметры запуска PostgreSQL,
  адрес слушающего сокета, master key и пути хранилища по-прежнему задаются
  установщиком/окружением, а не этим файлом.
- `sources`: список записей с постоянным уникальным `id`, `label`, `source_type`,
  `enabled` и `settings`. Типы: `imap`, `exchange`, `mts_link`, `external_tasks`.
  `enabled` по умолчанию `false`. Для неполных записей оставьте его выключенным:
  пользователь заполнит недостающие поля и включит источник в админке.
- Необязательный `llm_api_key` на верхнем уровне задаёт ключ провайдера LLM.
  Необязательный `sources[].credential` задаёт пароль IMAP/Exchange или access
  token МТС Линк. Для включённого почтового источника нужны все обязательные
  параметры подключения и credential. Пользовательские секреты имеют приоритет
  и сохраняются зашифрованными. Команда удаления ключа LLM в админке подавляет
  также ключ из JSON. Ключ из файла не передаётся на изменённый пользователем
  адрес LLM; для нового адреса нужно ввести свой ключ. Аналогично пароль источника
  из файла не используется при замене его адреса подключения.
- Размер файла ограничен 1 МиБ. JSON не поддерживает комментарии.

В типовом корпоративном шаблоне оставляйте секреты незаполненными. Если они всё же
передаются в файле, ограничьте права чтения учётной записью приложения и
администраторами. Политика доставки отвечает за права на файл.

В БД для файлового источника дополнительно хранится техническая запись с ID,
состоянием синхронизации и отпечатком конфигурации. Она нужна для внешних ключей
писем и результатов собраний; параметры из JSON в неё не копируются. Смена
файловых параметров источника сбрасывает курсор, чтобы не пропустить данные нового
подключения. Удалённый в админке файловый источник получает отметку удаления и
после перезапуска не восстанавливается; для нового источника используйте новый ID.
Исчезнувший из JSON источник отключается. Миграция схемы — `0025`; перед обновлением
сделайте резервную копию БД средствами вашей установки.

Android, iOS и web используют объединённые значения через серверный API.
Этот механизм не заменяет настройку адреса сервера или mTLS на мобильном устройстве.
